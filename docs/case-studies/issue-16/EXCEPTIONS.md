# Function-local C++ exceptions in C

The C++ program in the issue's editor screenshot executes `throw 8` inside
`main`, catches it as `int`, and returns the caught value. Both translators
previously rejected C output with `Exception translation is unavailable for c`.

```bash
node bin/universal-translator.js translate cpp c examples/translation/exceptions.cpp --all-or-nothing
node examples/translation/verify-exceptions.mjs target/debug/universal-translator
```

The readers record the exact C++ type when the throw operand is a plain
decimal `int` literal in the portable range, or its unary negation. They also
retain the exact type of simple catch declarations. Each C writer emits
scoped integer storage and branches to a local dispatch label. A throw enters
the first handler for that exact type or a catch-all. A bare rethrow passes
the saved exception to the enclosing dispatch, even when the handler has
mutated its own by-value parameter. A normal return leaves the function
without running a catch body.
[C++ draft on the throw expression](https://eel.is/c++draft/except.throw) ·
[C++ draft on handling an exception](https://eel.is/c++draft/except.handle) ·
[C++ draft on integer literals](https://eel.is/c++draft/lex.icon)

The native comparison builds the original C++ and compiles C generated by
each implementation in strict C99 mode. It compares status, standard output
and standard error. The original case returns 8. A second program returns 42
only after checking normal completion, skipped real and long handlers,
rethrow after mutation of a catch parameter, a new throw inside a catch, an
exception forwarded past an unmatched inner handler and generated-name
collisions. The original Python and JavaScript comparisons also run in the
verifier.

Calls and values that require unwinding, reference catches, throws that
escape the function, richer C++ payload types and reconstructing `Try` from
generated C are still open. The C writer rejects inputs outside its verified
exception subset. The remaining target languages are tracked in the active
requirements.
