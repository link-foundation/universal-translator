## Extending the verified boundary

The [readiness investigation](readiness.md) traces the solver's previous
ready transition. The archive check reports native coverage from real
executions and requires complete JavaScript and Rust coverage on a
ready-for-review PR 5. Coverage beyond those two source languages and the
remaining requirements above still need evidence.

Measure Rosetta Code support at a pinned revision. Define the observable
contract per task and classify every selected source by dialect, environment
and variant. Extend the typed effects and registries in both runtimes, then
require native verification for the new targets. Add grammar-specific
adapters when a task's variants cannot share a conservative scaffold. Keep
source spans and preserve unmatched text so the round trip can be tested
even where a semantic projection is unavailable.

For translations involving dependencies, resolve the source declarations and
entry point before changing the effect model. Produce target bindings for each
dependency and validate their output or side effects individually. Binary
support needs format-specific decoders and lifters that can build the same
representation from instructions. A proof target can then choose an explicit
observation model and validate each rewrite against it.

For natural-language translation, publish reproducible corpus queries, define
what counts as an observation, and validate the ranker on examples with
multiple intended readings. Keep absent evidence explicit and publish reverse
translations for auditing. Relative Meta Logic can express recursive
dependencies when the corpus and meaning sources are available.
