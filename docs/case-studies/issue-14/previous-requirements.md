# Previous requirements that are not delivered yet

Issue 14 asks to "collect all previous not delivered requirements from all issues (description + comments), pull requests (description, comments). Everything that is not yet done must be fully tracked".

This file is that inventory. It was built from the raw data in [`data/`](data/README.md): issues 1, 2, 6, 8, 10, 12 and 14, and pull requests 3, 4, 5, 7, 9, 11, 13 and 15. Every requirement the owner (`konard`) wrote is listed with the exact quote, the source and its status checked against the repository at commit `d09dc14` (branch `issue-14-213b02ae6953`) on 2026-11-26. The first check, at `b20bde4` (the start of PR 15), found most items open; every row that was not `done` there is checked again here by running the command named in its evidence, and the quoted output is the real output of that command. The older inventories (`docs/case-studies/issue-{1,6,8}/requirements.lino`) were not trusted: their `done` claims were re-checked, and `scripts/check-requirements.mjs` only verifies that evidence exists, not translation quality.

Statuses:

- `done`: delivered, with the file, test or command output that shows it.
- `partial`: some of it exists; the text says exactly what is missing.
- `not-done`: nothing, or only a stub, exists.
- `blocked`: it needs something outside the repository; the text says what.

The status is the state of the code at the head of PR 15 when this file was last changed.

Commands are shown as `translate ...`, `meta ...`, `detect ...` and `check-equivalence ...`; each runs as `node bin/universal-translator.js <command>`.

Where the owner wrote the same requirement more than once, it is listed once in the place it first appeared and the later quotes are added to it.
