# Previous requirements that are not delivered yet

Issue 14 asks to "collect all previous not delivered requirements from all issues (description + comments), pull requests (description, comments). Everything that is not yet done must be fully tracked".

This file is that inventory. It was built from the raw data in [`data/`](data/README.md): issues 1, 2, 6, 8, 10, 12 and 14, and pull requests 3, 4, 5, 7, 9, 11, 13 and 15. Every requirement the owner (`konard`) wrote is listed with the exact quote, the source and its status checked against the repository at commit `b20bde4` (branch `issue-14-213b02ae6953`). The older inventories (`docs/case-studies/issue-{1,6,8}/requirements.lino`) were not trusted: their `done` claims were re-checked, and `scripts/check-requirements.mjs` only verifies that evidence exists, not translation quality.

Statuses:

- `done`: delivered, with the file or test that shows it.
- `partial`: some of it exists; the text says exactly what is missing.
- `not-done`: nothing, or only a stub, exists.

Where the owner wrote the same requirement more than once, it is listed once in the place it first appeared and the later quotes are added to it.

## Cross-cutting findings

- The earlier inventories are optimistic. `docs/case-studies/issue-1/requirements.lino` lists only `rosetta-algorithm-types` and `class-fragments` as blocked. The check script only looks for evidence, so everything marked `partial` above passed it.
- The owner's wording "Nothing should be defered or delayed" appears in nearly every comment, but the descriptions of PR 5, 7 and 13 each close with a "blocked" or "Not done" list, and the following issues did not carry those lists forward. That is why issue 14 asks for tracking.
- `Example app` on `main` is red (run 45675992251): generated preview images drifted, and the job needs `RELEASE_PR_TOKEN` to push them.

## Concise list: everything partial or not-done

1. 1.1 / 12 P6: no ranking or round-trip-based choice in the translator pipeline; no corpus frequencies.
2. 1.2: no record of the imprecision or range of a statement in the meta tree.
3. 1.3 / 12 P12: the Hello World Collection corpus is not imported.
4. 1.4 / 6.8 / 14.1 / 12 P3: whitespace inside a line is lost (CST is not the default).
5. 1.7 / 6.9 / 14.7 / 12 P2: comments are not really translated (`// Привет мир` stays Russian); comment edits work only for the C to C# example.
6. 1.8 / 5.5 / 8.2 / 12 P7 / 14.16: Rosetta Code coverage is 39.4% of lines; floating point, strings, higher-order functions, data structures, I/O, objects and concurrency are blocked; there is no original-language round trip.
7. 1.9 / 12 P5, P10, B3: the Rust port has no `serve`, no Wikidata words and no Meta Language 1.0 `translate-program`.
8. 1.10 / 5.17: no decorator wrappers for readers, parsers and emitters (only rule lists are decoratable); the associative stack is only partly applied.
9. 1.12: no proof or checker of translation equivalence.
10. 1.13: no translation of standard and other libraries.
11. 1.14 / 14.14: machine code has one assembly dialect, no readers of binaries, no versions, and `nasm`, `cil` and `jvm` are not in the language list or pickers.
12. 1.16: no style translation (for example to a non-traditional C# style); the Russian to English comment case fails.
13. 1.18 / 12 B3: the relative-meta-logic probabilities and the Meta Language 1.0 module are not used.
14. 2.1 / 2.4 / 2.5: the package name is scoped (`@link-foundation/universal-translator`), not the unscoped name in the issue; first publication and the trusted publisher need the owner's npm access and are not verified.
15. 6.5 / 12 P4: versions exist only for `python@2` and British English; no versions for the other 31 languages.
16. 6.6: no matching of American or British English to the browser languages.
17. 6.10 / 8.1 / 12 P1: some natural-language wordings are not read (`while n is less than 3, do this`).
18. 6.13: no live recursive definition of unknown words from Wikidata; Rust lacks Wikidata at all.
19. 6.14 / 7.2 / 12.10: the earlier "everything is done" claims are not true; the items in this list are the undelivered rest.
20. 8.6 / 14.11: auto-detect fails on short or plain natural text (`Привет`).
21. 10.1: `Example app` on `main` is red because the preview images drifted.
22. 12 B2: no real numbers in the meta language (`7 / 2` becomes `Math.trunc`).
23. JavaScript arrow functions and classes are not read (PR 13 gap); classes as fragments are blocked (5.19).
24. 5.4: top 50 programming languages (14 of the TIOBE top 50 are missing) and plain natural-language descriptions of all algorithms.
25. 5.6 / 5.7: JavaScript and Rust round trip is verified only for the example programs, not for Rosetta tasks.
26. 5.8: inline `#[cfg(test)]` tests in `rust/src/natural/comments.rs` and `rust/src/formal/versions.rs` mix source and tests.
27. 5.9: the root cause is documented, but the upstream fix (link-assistant/hive-mind#3929) is open and full delivery did not happen.
28. 5.14 / 14.9 / 14.10: natural language is processed with flat templates, not a deep recursive grammar and dictionary with parts of speech.
29. 5.20: not every CI check on `main` is green (see 21).
30. 14.2: Monaco is not the default editor, and fold regions are not handled.
31. 14.3 to 14.5: no synchronised folding, selection, cursor and scrolling between the editors, and no mapping visualisation.
32. 14.6: `Comment language` and `Identifiers language` are not available on both sides.
33. 14.8: the option checkboxes are still above the editors.
34. 14.12: no deep parsing of natural-language comments, and no nesting of grammars inside one another.
35. 14.13: the meta language still has a special `print` node and is not generalised into plain calls.
36. 14.15: the owner's call to rethink and raise the quality of everything not best possible is open-ended and unresolved.
